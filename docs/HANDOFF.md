# Передача проєкту

Сайт розроблено студією Fooror. Під час розробки репозиторій і проєкт Vercel лежать на акаунтах студії, після здачі переходять власнику сайту.

## Що входить у передачу

| Що | Де живе | Стан |
|---|---|---|
| Код | GitHub, репозиторій `zhukov` | на акаунті студії |
| Хостинг | Vercel, проєкт `zhukov` | ще не створено |
| Домен | реєстратор власника | ще не підключено |
| Telegram-бот для заявок | BotFather на акаунті власника | ще не створено |

Цю таблицю оновлюємо на кожному кроці.

## Порядок передачі

1. **GitHub.** Власник створює акаунт. Студія: Settings → General → Transfer ownership, вказує його акаунт. Власник підтверджує лист. Історія комітів зберігається.
2. **Vercel.** Власник створює акаунт і команду. Студія: Project Settings → General → Transfer Project. Після переносу перевірити три речі: проєкт звʼязаний із репозиторієм на новому акаунті GitHub, змінні середовища на місці, домен привʼязаний.
3. **Тариф Vercel.** Безкоштовний Hobby за умовами Vercel призначений для некомерційних проєктів. Сайт бізнесу має працювати на Pro.
4. **Домен.** Лишається в реєстратора власника. DNS-записи, які треба додати, показує Vercel у Project Settings → Domains.
5. **Telegram-бот.** Після переносу власник перевипускає токен у BotFather (`/revoke`) і вписує новий у Vercel: Project Settings → Environment Variables → `TELEGRAM_BOT_TOKEN`, далі Redeploy.
6. **Індексація.** На бойовому домені виставити `ALLOW_INDEXING=true` і `SITE_URL=https://домен`.
7. **Контрольна правка.** Власник клонує репозиторій, просить свій Claude змінити будь-який текст за `docs/CONTENT.md`, отримує превʼю і публікує. Передача вважається завершеною, коли цей крок пройшов.
8. Студія виходить із доступів або лишається учасником, якщо домовлено про супровід.

## Змінні середовища

Повний перелік із поясненнями: `.env.example`. Секрети передаються через менеджер паролів, не в листуванні.
