# Сайт Артура Жукова

Лендінг Growth / CGO консультанта. Одна сторінка, анкета в попапі, сторінка подяки `/thanks`. Мова сайту українська.

@AGENTS.md

## Стек

Next.js 16 (App Router), React 19, TypeScript strict, Tailwind CSS v4. Хостинг Vercel, код на GitHub. Бази даних і CMS немає.

Next.js тут новіший, ніж у більшості навчальних даних. Перед тим як писати код із його API, прочитай відповідний розділ у `node_modules/next/dist/docs/`.

## Команди

```bash
npm install        # один раз після клонування
npm run dev        # http://localhost:3000 (відкривати саме localhost, не 127.0.0.1)
npm run check      # lint + типи + збірка, запускати перед кожним пушем
```

Потрібен Node.js 22 або новіший.

## Правила

1. **Контент окремо від верстки.** Тексти й числа живуть у `src/content/`. Компоненти отримують їх через функції з `src/lib/content.ts` і ніколи не імпортують `src/content/*` напряму. Це місце, куди пізніше підключиться адмінка.
2. **Значення дизайну беруться з токенів.** Не пиши довільні кольори й розміри в класах, якщо в `@theme` вже є відповідний токен. Новий токен додавай у `@theme` з коментарем, звідки він.
3. **Серверні компоненти за замовчуванням.** `"use client"` став лише там, де потрібні стан чи події браузера (попап, акордеон, анімація).
4. **Швидкість.** Ціль 90+ у PageSpeed на телефоні. Зображення тільки через `next/image` із заданими `sizes`; для головного фото секції `preload` (властивість `priority` у Next 16 застаріла). Важкі бібліотеки (GSAP) підключаються динамічним імпортом і лише в тій секції, якій потрібні.
5. **Рух.** Прості появи на CSS. Ефекти на WebGL пишемо без бібліотек, спільні частини в `src/lib/webgl.ts`: цикл кадрів сам зупиняється, коли блок поза екраном або вкладка прихована. На телефоні складні анімації вимкнені, а не спрощені на ходу. `prefers-reduced-motion` уже враховано в `globals.css`.
6. **Фокус.** Рамка зʼявляється тільки при навігації клавіатурою і малюється зовні елемента. Це вже зроблено глобально, не перевизначай.
7. **Секрети.** Токени й ключі лежать лише в `.env.local` і в налаштуваннях Vercel. У git вони не потрапляють. Перелік змінних: `.env.example`.

## Як публікувати зміни

1. Створи гілку від `main`, внеси зміни, запусти `npm run check`.
2. Запуш гілку. Vercel збере превʼю і дасть посилання для перегляду.
3. Якщо все гаразд, злий гілку в `main`. Vercel опублікує бойову версію за хвилину-дві.

Пуш у `main` одразу змінює живий сайт, тому напряму туди не пушимо.

## Перевірка після змін

- `npm run check` проходить без помилок.
- Сторінка виглядає правильно на ширинах 390, 768, 1440 і 1920.
- Якщо чіпав анкету: порожня відправка показує помилки, заявка без жодного контакту не проходить, успішна веде на `/thanks`. Локально з `LEAD_DRY_RUN=true` заявка друкується в термінал замість Telegram.
